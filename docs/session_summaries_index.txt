### 2. PrimeNG to NG-ZORRO Migration
**File:** `docs/SESSION-FORK-DESCISION.md`  
**Date:** October 5, 2025  
**Branch:** `feature/ng-zorro-migration`  
**Status:** ✅ **COMPLETED** - Migration Successful

**Original Goal:**
Evaluate and potentially migrate from PrimeNG to NG-ZORRO due to licensing concerns.

**Summary:**
- Discovered PrimeNG 13.4.x requires commercial license ($590/year)
- Researched NG-ZORRO as MIT-licensed alternative
- Evaluated risk, community health, and corporate backing
- Successfully migrated entire table component to NG-ZORRO
- Removed all PrimeNG dependencies

**Key Decisions:**
- **Decision:** Migrate to NG-ZORRO (Ant Design for Angular)
- **Rationale:** MIT license, Alibaba backing, active development
- **Risk Assessment:** Low risk of license change due to corporate use
- **Result:** Successful migration, better visual design

**Technologies Changed:**
- **Removed:** PrimeNG 13.4.5-lts
- **Added:** ng-zorro-antd 13.4.0
- **Impacted:** Results table, form inputs, buttons, UI components

**Related Changes:**
- Complete table component rewrite (`results-table.component.ts/html`)
- Updated module imports in `app.module.ts`
- Consistent Ant Design aesthetic across application

**Current State:** NG-ZORRO in production (v1.0.7), no licensing issues

### 3. Server-Side Column Filtering Implementation
**File:** `docs/SESSION-FORK-DESCISION.md` (same session as migration)  
**Date:** October 5, 2025  
**Backend Version:** v1.0.4  
**Status:** ✅ **COMPLETED** - Fully Functional

**Summary:**
- Implemented server-side column filtering for all table columns
- Added 7 filter parameters to backend API
- Integrated filters with URL state management
- Implemented 500ms debounce on filter inputs
- Filters work seamlessly with sorting and pagination

**Architecture Decision:**
Chose **server-side filtering** over client-side due to:
- Incompatibility of PrimeNG client filters with server pagination
- State conflicts between client and server
- Scalability for large datasets (300k+ records)
- Consistency with existing sorting pattern

**Technical Implementation:**

**Backend (`searchController.js`):**
- Wildcard filtering for text fields (case-insensitive)
- Numeric range filtering for year fields
- All filters added to Elasticsearch `must` clause (AND logic)

**Frontend:**
- Extended `SearchFilters` model with filter properties
- URL serialization via `RouteStateService` (short params: fReg, fMfr, etc.)
- Debounced filter inputs using RxJS Subject
- Filter state persistence in URL

**Filter Parameters:**
```typescript
filterRegistration  // Registration ID
filterManufacturer  // Manufacturer name
filterModel         // Model name
filterYearMin       // Minimum year
filterYearMax       // Maximum year
filterCategory      // Aircraft category/type
filterState         // State/province
```

**Current State:** Production-ready, filters working with all features
